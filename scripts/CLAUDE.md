# Sleeper-side scripts and timers

These run on the **Sleeper host only**, not in the Worker. Each reads Reader
credentials from `~/.config/reader/env` (`READER_API_URL` + `READER_MCP_TOKEN`).
systemd **user** timers (`Persistent=true`) are vendored under `scripts/systemd/`.

`journalctl --user -u <name>` to tail; `systemctl --user start <name>.service` to run now.

## The Found feed and its collector seam

A push-only feed (`Feed.kind='found'`, `is_active=0`) that collects bookmarks/saves from social sources — X bookmarks today, more later. It behaves like any other feed (its unread articles flow into the main Deck and it lists under Sources) **and** has a dedicated **Found** tab in `BottomBar` (`pages/found.vue` → a `DeckScreen` scoped to the Found feed; the five verbs work, so swipe-up elevates a found item straight into SFL→wiki).

- **Reader stays source-agnostic.** Source-specific logic lives in per-source collectors that normalize each item and POST to `/api/ingest` — except X, which is now **in-Worker** (see next bullet). Adding a new source = a new collector, zero Reader changes. `Article.source` records per-item origin (`'x-bookmark'`, `'bluesky'`, `'mastodon'`, `'reddit'`, `'instapaper'`, `'ai-digest'`, `'sleeper-articles'`, …). Six Sleeper-side collectors remain (all Sleeper-only, like `feed-candidates.mjs`); each reads Reader creds from `~/.config/reader/env` (`READER_API_URL` + `READER_MCP_TOKEN`). Four normalize *one social item → one card*; the AI digest reads *many* SFL ideas and synthesizes *one* card; the Sleeper Articles collector mirrors *one already-extracted article → one card*.

The four **linked sources** (X, Reddit, Hacker News, GitHub) are Worker-side instead —
see [`../server/CLAUDE.md`](../server/CLAUDE.md).

## Collectors

- **Bluesky collector**: `scripts/bluesky-bookmark-sync.mjs`. Lowest-friction — free app password, no OAuth dance, no per-call cost. Opens/refreshes an AT Protocol session (`createSession`/`refreshSession`), pages newest-first through native bookmarks (`app.bsky.bookmark.getBookmarks`), renders each from the hydrated `postView` (text + images + quoted post + link card, no extra fetches), POSTs as `source=bluesky` with `externalId` = the post `at://` URI. Config in `~/.config/bluesky/{env,token.json,state.json}` — `env` holds `BLUESKY_IDENTIFIER`, `BLUESKY_APP_PASSWORD`, optional `BLUESKY_PDS`. Flags: `--dry-run`, `--verbose`, `--max-pages N`.
- **Mastodon collector**: `scripts/mastodon-bookmark-sync.mjs`. Free + friction-light like Bluesky — auth is a personal access token (`read:bookmarks` scope), no OAuth dance. Pages `GET /api/v1/bookmarks` following the `Link: rel="next"` header (Mastodon paginates bookmarks by an internal bookmark id only exposed there, not the status id), renders each Status from the object (HTML content + media + boosted `reblog` + link `card`), POSTs as `source=mastodon` with `externalId` = status id. Config in `~/.config/mastodon/{env,state.json}` — `env` holds `MASTODON_INSTANCE` + `MASTODON_ACCESS_TOKEN`. Flags: `--dry-run`, `--verbose`, `--max-pages N`.
- **Reddit collector**: `scripts/reddit-saved-sync.mjs`. Reddit's analog to bookmarks is the **saved** list (saved posts AND comments). OAuth2 "script" app password grant (mints a fresh ~1h token per run — no refresh bookkeeping), pages `GET /user/{username}/saved` with `raw_json=1` following the `after` cursor, renders `t3` posts (title/selftext/preview image/external link) and `t1` comments (body + thread title) from the listing. POSTs as `source=reddit` with `externalId` = the fullname (`t3_…`/`t1_…`). Requires a unique `User-Agent` (Reddit 429s without one). Config in `~/.config/reddit/{env,state.json}` — `env` holds `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`, `REDDIT_USERNAME`, `REDDIT_PASSWORD`, optional `REDDIT_USER_AGENT`. Flags: `--dry-run`, `--verbose`, `--max-pages N`.
- **Instapaper collector**: `scripts/instapaper-sync.mjs`. Natural fit (a save-for-later service). OAuth 1.0a **xAuth** (HMAC-SHA1 signing hand-rolled with `node:crypto`, verified against the `oauth-1.0a` vector), `bookmarks/list` on a folder (default `unread`), best-effort `bookmarks/get_text` for full article bodies, POSTs as `source=instapaper` with `externalId` = `bookmark_id`. Config in `~/.config/instapaper/{env,token.json,state.json}`. **Gated** on a consumer key/secret from Instapaper's human-reviewed [request form](https://www.instapaper.com/main/request_oauth_consumer_token) — throws until present, so the timer is harmless meanwhile. Flags: `--dry-run`, `--verbose`, `--folder NAME`, `--no-text`.
- **AI digest collector**: `scripts/ai-digest-sync.mjs`. The odd one out — reads *many → one*. Pulls the last ~26h of SFL ideas tagged `ai-news` (`GET /api/ideas?tag=ai-news` — reads the **tag**, not the producing job, so the recurring AI-discovery job can evolve underneath it), asks an LLM (**Venice.ai** OpenAI-compatible API, model `zai-org-glm-5-2`, plain `fetch`, no SDK dep) for a calm editor's-letter HTML digest grouped into 2–4 themes with each claim linked to its source, and POSTs **one** card as `source=ai-digest` with `externalId=<YYYY-MM-DD>` (guid `ai-digest:<date>`, idempotent per day). glm reasons before answering, so the call sets `venice_parameters.disable_thinking`+`strip_thinking_response`; `extractFragment()` strips any reasoning preamble/fence. `ai-news` ideas are mostly `type:note` with `url=null` (source link in the body) — `sourceUrl()` recovers it, `unwrapDeadLinks()` strips any `href="#"` the model invents. Empty window → posts nothing; LLM failure → deterministic linked-list fallback. Config in `~/.config/ai-digest/{env,state.json}` — `env` holds `SFL_API_URL`, `SFL_API_KEY`, `VENICE_API_KEY` (falls back to shell `VENICE_API_TOKEN`), optional `DIGEST_MODEL`/`VENICE_API_URL`/`DIGEST_WINDOW_HOURS`. Flags: `--dry-run`, `--verbose`, `--window-hours N`, `--date YYYY-MM-DD`, `--replace` (rebuild an already-posted day in place via the ingest `replace` flag). Design: [`docs/found-feed-ai-digest.md`](../docs/found-feed-ai-digest.md). **Timer disabled 2026-08-05** (Petter turned the daily digest card off; `systemctl --user enable --now ai-digest-sync.timer` to resume).
- **Sleeper Articles collector**: `scripts/sleeper-articles-sync.mjs`. Mirrors the Sleeper Articles service (`~/chat/articles` — the SFL-bookmark extraction pipeline on `127.0.0.1:3003`) into Found. Reads *one already-extracted article → one card*: pages the articles list newest-first (`GET /?status=ready&cursor=…`, cursor pagination via `next_cursor`/`has_more`), stopping once a page is not entirely new (bounded by `--page-size`/`--max-pages`/`--max-items`), then fetches each new item's full doc (`GET /:id` — the list view strips `content_md`) and renders **by kind**: `article`/`digest` bodies via a vendored dependency-free Markdown→HTML converter (`mdToHtml`, since `marked` isn't a Reader dep; `inline()` covers `_underscore emphasis_` only when whitespace-flanked, so snake_case and URL underscores survive), `video` as a thumbnail+link card, `post` as an X-style card from `doc.post_data`. **Post media branches on `m.type`** (`mediaBlock`): photos become `<img>`, video/animated_gif become a real `<video controls playsinline preload="metadata" poster>` pointing at the mp4 the Articles service already picked — `XMedia.url` is the *highest-bitrate mp4* for video, so rendering it as `<img>` (as this did until 2026-07-27) yields a permanently broken image. The card lead image (`postLeadImage`) is always a still: a photo's `url` or a video's `poster_url`, never an mp4. POSTs as `source=sleeper-articles` with `externalId=<article id>` (guid `sleeper-articles:<id>`, idempotent). The list/read endpoints are public today, so `ARTICLES_API_KEY` is optional. **The Articles service already holds hundreds of ready items**, so `--seed` marks the current backlog seen without ingesting (run once to establish a baseline — done 2026-07-01, 500 seeded + 3 test cards kept); normal runs then pull only genuinely new articles. Config in `~/.config/sleeper-articles/{env,state.json}` — `env` holds `ARTICLES_API_URL` (default `http://127.0.0.1:3003`) + optional `ARTICLES_API_KEY`. Flags: `--dry-run`, `--verbose`, `--show-html` (print the rendered body + lead image instead of just the title — pair with `--dry-run --ids <id>` to eyeball a rendering change before it ships), `--seed`, `--ids a,b,c` (force-ingest exactly these ids, bypassing paging + the seen-set), `--kinds a,b` (only ingest these kinds; default `READER_SYNC_KINDS` from the env file, else all — filtered items are marked seen, and the filter applies to `--ids` force pushes too, so a starred non-matching article is dropped like any other), `--page-size N`, `--max-pages N`, `--max-items N`. **Since 2026-08-05 the env file sets `READER_SYNC_KINDS=digest`** — only digest cards (obsession brief, morning brief, X vibe cards) reach Found; the article/video/post mirror and the starred force-push are off. Remove the line to resume full mirroring (the meanwhile backlog stays seen, so no flood). **Digests rebuild in place (2026-07-28):** a `digest` row is upserted upstream (`POST /digest` is idempotent per ISO week), so a re-push carries a *rewritten* essay under an id Reader already knows — those cards go out with the ingest `replace: true` flag (rebuilt body, back to unread), counted as `rebuilt` in the run summary. Every other kind is immutable once ready, so its re-send stays a no-op. The Sunday obsession brief is the only producer today (`byline: 'Sleeper · obsession brief'` → card author; summary = the week's top cluster labels; url falls back to the article's public `content_url`, since a digest's own url is the synthetic `sleeper://digest/<key>`). **Push-on-ready (2026-07-12):** the Articles service now also triggers this collector itself — on ready-transitions, on `starred: true` PATCHes (the "best content" signal; `--ids` reaches even seeded-out backlog items), and on digest upserts — via `~/chat/articles/src/services/reader-push.ts` (debounced 45s, killswitch `READER_PUSH_ENABLED`); both that spawn and the systemd unit take `flock ~/.config/sleeper-articles/.lock` so runs serialize instead of racing on `state.json`, and the 08/20:20 timer stays as the safety net. Note this partly overlaps upstream sources: these articles originate from SFL bookmarks, and Reader's swipe-up elevate writes *back* to SFL — dedup is by guid, but the same X post can appear both as an `x-bookmark` card and a `sleeper-articles` `post` card.

## Discover candidate collectors

These normalize their finds and POST to `POST /api/discover/candidates` — Reader stays
source-agnostic, exactly like the Found feed's collector seam. The crawl itself is
Worker-side ([`../server/CLAUDE.md`](../server/CLAUDE.md)).

- **More sources** (beyond the blogroll graph): collectors normalize their finds and POST to `POST /api/discover/candidates` — Reader stays source-agnostic, exactly like the Found feed's collector seam. `scripts/hn-frontpage-candidates.mjs` (weekly `reader-hn-candidates.timer`, Mon 07:10): one Algolia HN API call for 30 days of front-page stories → domains with ≥3 appearances (capped 20, big-media/platform hosts excluded) → source `hn-frontpage`, label "Hacker News front page". `scripts/feed-candidates.mjs` (the monthly SFL-saves miner) now also pushes its shortlist (only candidates with a working feed) as source `sfl-saves`, label "Your SFL saves" — `--no-push` opts out; it still never auto-subscribes. `scripts/ooh-directory-candidates.mjs` (weekly `reader-ooh-candidates.timer`, Wed 07:15): mines [ooh.directory](https://ooh.directory) (Phil Gyford's hand-curated ~2,400-blog directory) — a hand-written `TAG_CATEGORIES` map in the script turns the user's feed tags into directory categories, a round-robin cursor covers 3 categories per run, entries quiet >365 days are skipped, and each new blog's "More info" page is scraped for the exact RSS URL so candidates POST **with `feedUrl`** and skip the expensive resolve stage; seen-set + cursor persist in `~/.config/reader/ooh-state.json`; polite scraping (first category page only, ≤20 info pages/run, 400ms delays, honest bot UA). Flags: `--dry-run`, `--verbose`, `--categories a/b,c/d`, `--per-run N`, `--max N`, `--max-age-days N`. Labeled sources render in the via-line just like feed titles (`COALESCE(f.title, e.label)`), and a candidate recommended by both a blogroll and HN ranks `via 2`.

## Feed-candidate report

`node scripts/feed-candidates.mjs` mines the SFL save stream (`~/chat/articles/data/articles.db`) for domains worth subscribing to, weighted by thoughts-wiki provenance folds (`~/thoughts/sync/provenance.json` + raw frontmatter), excludes domains already subscribed (via `GET /api/feeds`), and probes survivors for working RSS/Atom feeds. Reader API auth from `~/.config/reader/env` (`READER_API_URL` + `READER_MCP_TOKEN`). Runs monthly via recurring sleeper-task #73 (`DO-PADDLE-CRISPED-CLASP`, cron `0 8 1 * *`), which posts the shortlist as a task comment — it never auto-subscribes. Since 2026-07-18 it also pushes candidates with a working feed into `/discover` via `POST /api/discover/candidates` (source `sfl-saves`; `--no-push` opts out). Flags: `--json`, `--min-score N` (default 4), `--no-push`.
